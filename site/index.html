04Session replay

See what users did. Never what they typed.

Replays record a wireframe of the screen, not pixels. Text is masked on the device before anything is sent, so card numbers, PAN and passwords never reach a replay.

  • Masked on the device. Not scrubbed later on a server. Opt elements in or out with selectors.
  • Frustration on the timeline. Rage taps, dead taps, errors and network breadcrumbs, flagged.
  • Linked to your funnels. From any drop-off, jump straight to the sessions of users who left.

05Feature flags and experiments

Ship features with confidence.

Roll out behind a flag, run the experiment, and read the result next to the same funnels and replays. Flags are evaluated locally in the SDK, so there is no network round trip on the hot path.

  • Targeted rollouts. Percentages and rules on user properties.
  • Experiments with guardrails. Conversion lift and sample-ratio checks built in.
  • Local evaluation. Consistent bucketing in the SDK and at the edge.

07Architecture

One binary.
No cluster to babysit.

Ingest, storage, the query engine, Studio and the MCP server run in a single Rust process. Point it at a local disk or any S3-compatible bucket and you are done.

Event ingestion

Batches events, merges identities and writes a WAL for durability. Pushes back with 429 under load.

Columnar storage

Immutable segments partitioned by project, day and bucket, sorted by user and session.

Query engine

Funnels, retention, journeys and insights as scans over user-ordered columns.

01

Wireframe replay, masked on the device

Replays capture layout, not pixels, and text is masked before it is sent. Event properties are sent as you pass them, so keep secrets out of them.

02

Erasure and opt-out APIs

Per-user erasure with an audit record of every deletion, plus SDK opt-out for consent flows. Built with India's DPDP Act in mind.

03

Self-hosted by default

Run it in your VPC or region. Use your disk's or bucket's own encryption for data at rest.

10Developers

From zero to analytics in minutes.

Build and run one binary, add a few lines of SDK, and send your first event. Or hand the whole setup to your coding agent.

# Build the Studio UI and the node
$ npm --prefix web ci && npm --prefix web run build
$ cargo build --release -p pulse-node

# Start with a demo dataset
$ export PULSE_ADMIN_TOKEN="sk_root_$(openssl rand -hex 24)"
$ ./target/release/pulse-node --port 8080 --data-dir ./pulse_data --seed

# Studio, API and MCP:  http://127.0.0.1:8080
# Sign in with the admin token. Without PULSE_ADMIN_TOKEN, one is written to
# pulse_data/root_admin_token. The first ingest key is printed in the startup log.
import { PulseWebClient } from "@pulse-analytics/ts-web";

const pulse = new PulseWebClient({
  endpointUrl: "http://127.0.0.1:8080", // your node
  apiKey: "pk_live_…",                  // an ingest key, never an sk_ key
  autocapture: true,
  enableWireframeReplay: true,
});

pulse.track("Checkout_Started", { cart_value: 99, currency: "USD" });
await pulse.identify("usr_1042", { plan: "pro" });

Not on npm yet: install the packed .tgz from the latest release or build locally from sdks/ts-web. Web SDK guide →

Set up Pulse (open-source product analytics, https://github.com/sswapnil2/analytics-system) for this project.

1. Clone https://github.com/sswapnil2/analytics-system into ../pulse (skip if it exists).
   In that folder run:
     npm --prefix web ci && npm --prefix web run build
     cargo build -p pulse-node
2. Create a root admin token with `openssl rand -hex 24`, prefixed with `sk_root_`.
   Save it as PULSE_ADMIN_TOKEN in ../pulse/.env (create the file, never commit it).
   Start the node in the background from ../pulse:
     PULSE_ADMIN_TOKEN=<token> ./target/debug/pulse-node --port 8080 --data-dir ./pulse_data
   Wait until `curl -s http://127.0.0.1:8080/v1/status -H "Authorization: Bearer <token>"` succeeds.
3. Create two keys for the default project `proj_default` with
   POST http://127.0.0.1:8080/v1/projects/proj_default/api-keys (Bearer <token>, JSON body):
     {"label": "web app", "role": "ingest_and_flags"}  -> pk_live_… ingest key for the app
     {"label": "agent",   "role": "admin"}             -> sk_live_… project admin key for MCP
   Each `plaintext_key` is shown only once; keep both in ../pulse/.env.
4. If this project is a browser app, follow ../pulse/docs/web-sdk.md: install ../pulse/sdks/ts-web,
   initialise PulseWebClient with endpointUrl http://127.0.0.1:8080 and the pk_live_ key read from
   an environment variable, call identify() after login, and track() the 5–10 events that matter most
   for this product (sign-up, activation, the core action, purchase). Show me the event list first.
5. Connect yourself to Pulse over MCP using ../pulse/docs/mcp.md. URL http://127.0.0.1:8080/v1/mcp,
   bearer token = the sk_live_ admin key. In Claude Code you can instead install the plugin:
   /plugin marketplace add sswapnil2/analytics-system  then  /plugin install pulse@pulse
6. Send one test event to /v1/ingest, then confirm it through MCP, and tell me the Studio URL
   (http://127.0.0.1:8080) and where the tokens are saved.

Questions, answered.

Is it really open source?

Yes. The code is Apache-2.0: run it, modify it and redistribute it, including commercially.

Do I need a licence key?

No. Every feature, including the AI Copilot, warehouse export, audit log and webhook alerts, is Apache-2.0 and works without a key. There are no event or seat limits.

Where is my data stored?

On the disk or S3-compatible bucket you point Pulse at. For encryption at rest, enable your disk's or bucket's own encryption.

Can it replace my current product analytics tool?

For funnels, retention, cohorts, flags and replay, yes. The web SDK captures page views, clicks and UTM parameters, and the import API backfills history. Multi-touch attribution reports aren't built yet.

How fast is it, really?

On one M2 Pro laptop with 1M events, a warm 5-step funnel takes 14.5 ms at p50 and ingest runs at about 249k events per second. Run scripts/bench_scale.sh 1m to measure your own hardware.

Will it stay free?

Pulse has one edition, and it is Apache-2.0.
